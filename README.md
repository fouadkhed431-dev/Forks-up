# Forks Up — HALL NO. 213

**Bite Together. Order Smarter.**

تطبيق ويب عربي RTL لإدارة طلبات الطعام الجماعية داخل المكتب. المسؤول يدير الجولات من لوحة محمية، والموظفون يفتحون رابط الجولة أو يمسحون QR Code من الهاتف دون تنزيل التطبيق أو إنشاء حساب.

## المزايا الحالية

- لوحة مسؤول محمية بتسجيل الدخول عبر Supabase Auth.
- إنشاء جولات طعام وتحديد نوع الطعام وموعد إغلاق الطلبات.
- إرفاق منيو المطعم كصورة JPG / PNG / WEBP أو PDF (حتى 10 MB).
- رابط فريد وQR Code لكل جولة، مع مشاركة الرابط والتذكير اليدوي عبر WhatsApp.
- صفحة طلبات للموظفين تعمل على الهاتف وباللغة العربية.
- طلب واحد لكل اسم داخل الجولة، ويمكن أن يحتوي الطلب عدة أصناف.
- كل صنف فردي أو مشترك؛ صاحب الطلب يدخل تلقائياً ضمن المشاركين في الصنف المشترك.
- منع الطلبات المكررة بالاسم نفسه داخل الجولة.
- تعديل أو حذف الطلبات بواسطة المسؤول أثناء فتح استقبال الطلبات.
- تسجيل عمليات الإضافة والتعديل والحذف في سجل خاص.
- تجميع الأصناف المتطابقة والكميات المطلوبة للمطعم.
- إدخال سعر الوحدة من فاتورة المطعم.
- حساب الصنف الفردي بالكامل على صاحبه، وتقسيم الصنف المشترك بالتساوي على المشاركين المحددين.
- تقسيم التوصيل والمصاريف الإضافية بالتساوي على جميع المشاركين في الجولة.
- كشوف حساب مفصلة فردية وجماعية، بصيغة نص أو صورة، مع المشاركة عبر WhatsApp.
- تحديث مباشر للوحة المسؤول عند وصول طلبات جديدة.
- أرشيف الجولات والبحث والتكرار والإحصائيات.
- تصدير نسخة احتياطية JSON واستعادة/دمج بياناتها.
- تطبيق PWA قابل للتثبيت على Android للمسؤول.

## الميزات التي لا يستخدمها الإصدار الحالي

تم حذف دليل الموظفين المستقل، والأصناف المفضلة، وتسجيل المدفوعات والتسوية، وإشعارات المتصفح. أسماء الموظفين تُقترح من طلبات الجولة الحالية فقط، ويمكن إرسال تذكير يدوي عبر WhatsApp.

## المتطلبات

- Node.js 20 أو أحدث.
- مشروع Supabase.
- استضافة HTTPS مثل Cloudflare Pages أو Vercel أو Netlify.

## إعداد قاعدة البيانات

1. أنشئ مشروع Supabase.
2. افتح SQL Editor ونفّذ ملف التأسيس supabase/migrations/202611170001_initial_schema.sql إذا كنت تنشئ قاعدة جديدة.
3. للمشروع الذي سبق إعداده، نفّذ ملفات الترقية بالترتيب الذي لم يسبق تطبيقه:
   - supabase/migrations/202611180001_unified_upgrade.sql (ترقية سابقة؛ لا تعِد تشغيلها إذا كانت قد نُفذت).
   - supabase/migrations/202611180002_remove_optional_tables.sql لإزالة الجداول الاختيارية بعد تحديث الدوال التي كانت تعتمد عليها.
4. من Authentication → Users أنشئ حساب المسؤول بالبريد وكلمة المرور، وتأكد من تأكيد الحساب.

لا تنفّذ ملف تأسيس قاعدة جديدة فوق قاعدة مستخدمة بالفعل. احتفظ بنسخة احتياطية قبل أي ترقية أو تغيير يدوي في قاعدة البيانات.

## إعداد مفاتيح الاتصال

من Project Settings → API في Supabase انسخ Project URL وPublishable key (أو anon/public key)، ثم أضفهما إلى متغيرات بيئة البناء:

    VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
    VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY

لا تضع مفتاح service_role أو أي Secret key في التطبيق أو GitHub أو متغيرات الواجهة.

## الاختبار والبناء محلياً

    npm install
    npm test
    npm run build
    npm run preview

## النشر والتثبيت على Android

1. اربط مستودع GitHub بخدمة الاستضافة.
2. أمر البناء: npm run build.
3. مجلد النشر: dist.
4. أضف متغيري البيئة المذكورين أعلاه في إعدادات الاستضافة.
5. افتح رابط التطبيق من Chrome على هاتف المسؤول واختر Install app أو Add to Home screen.

الموظفون يفتحون رابط الجولة مباشرة من WhatsApp أو الكاميرا، ولا يحتاجون إلى تثبيت Forks Up.

## العمل دون اتصال

يخزن Service Worker ملفات واجهة التطبيق وملفات البناء الثابتة التي تم فتحها بنجاح، ويتيح إظهار هيكل التطبيق عند انقطاع الاتصال بعد أول تحميل ناجح. إنشاء الجولات والطلبات وتحديثها والفواتير والنسخ الاحتياطي تحتاج إلى اتصال إنترنت لأن البيانات محفوظة في Supabase. التخزين المؤقت لا يعني أن التطبيق يدعم إدخال الطلبات دون اتصال.

## قواعد الحساب المعتمدة

- الصنف الفردي: كامل سعره على صاحب الطلب.
- الصنف المشترك: سعر الصنف × الكمية، ثم يقسم بالتساوي على صاحب الطلب وبقية المشاركين المحددين.
- التوصيل والمصاريف الإضافية: تقسم بالتساوي على جميع المشاركين في الجولة، بمن فيهم من شارك في صنف مشترك ولم يرسل طلباً منفصلاً.
- توزع فروق القروش بحيث يظل مجموع كشوف الأشخاص مطابقاً لإجمالي الفاتورة.

## النسخ الاحتياطي

يصدر التطبيق بيانات الجولات والطلبات والأصناف والأسعار وسجل التعديلات في ملف JSON. لا يتضمن الملف محتوى ملفات المنيو المرفوعة إلى Supabase Storage؛ احتفظ بنسخ ملفات المنيو المهمة بشكل منفصل. الاستعادة تدمج البيانات ولا تحذف السجلات الحالية.

## الأمان

- لا يوجد تسجيل عام للموظفين.
- لا يستطيع الزائر قراءة طلبات زملائه؛ إرسال الطلبات العامة يتم عبر RPC مخصص يتحقق من رمز الجولة وحالتها.
- يجب أن تظل سياسات RLS مفعلة على الجداول، وأن تقيد بيانات المسؤول بجولات حسابه.
- المفتاح العام الخاص بـ Supabase ليس بديلاً عن سياسات RLS. لا تستخدم مفتاحاً سرياً في الواجهة.

## الملفات المهمة

- src/: واجهة التطبيق ومنطق الحسابات والاتصال بقاعدة البيانات.
- supabase/migrations/: مخطط قاعدة البيانات وسياسات الأمان ودوال RPC.
- tests/: اختبارات قواعد الحساب.
- public/: شعار التطبيق وملفات PWA وService Worker.
- .env.example: مثال لمتغيرات الاتصال دون أسرار.
